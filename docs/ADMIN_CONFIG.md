# 管理台配置编辑方案

> 目标：管理员在 Web 管理台可视化维护游戏内容（物品/技能/任务/怪物/地图），
> 保存即写入数据库并热重载生效，无需重启、无需手编文件。

> 本文讲**设计与数据结构**。面向服主/策划的**操作手册**见
> [ADMIN_GUIDE.md](ADMIN_GUIDE.md)。

## 架构原则

1. **数据库是唯一真源**（2026-08 起）。物品/技能/任务/区域全部存于 SQLite
   配置表（`cfg_items`/`cfg_skills`/`cfg_quests`/`cfg_quest_objectives`/
   `cfg_zones`/`cfg_portals`/`cfg_spawns`/`cfg_drops`，规范化列而非 JSON blob），
   与角色存档同库。`server/data/*.json` 与 `zones/*.json` 降级为**首次建库时的
   种子数据**：库为空才导入一次，之后运行期不再读写文件。
2. **服务器是唯一校验点**。schema 反序列化 + 业务校验（id 唯一、槽位合法、任务
   前置存在、掉落表引用的物品模板存在）；校验失败拒绝写入并回显错误。
3. **写入 = 事务替换 + 重建内存快照**。管理台保存走整表事务替换，成功后重建
   `GameData` 内存快照（游戏逻辑同步读，不碰数据库）。
4. **热重载按数据类别分级**：
   - 物品/技能/任务：保存即热载（运行时表替换 + 在线玩家技能表即时重推）；
   - 区域怪物刷新/传送门：保存后重建该区怪物（P2）；
   - 新地图接入：涉及行走网格构建，保存边车后提示重启（P2 做成免重启）。

## 分期

### P1 数值表编辑（本期）
- API（沿用 x-admin-token 鉴权）：
  - `GET  /api/config` — 当前生效配置（items/skills/quests）
  - `PUT  /api/config` — 校验 → 写库（事务）→ 热重载 → 推送在线玩家
- 管理台"配置"页签：物品/技能/任务三张可编辑表格（新增/删除/改行），
  保存按钮，错误行内回显。
- 运行时：`GameData` 由 OnceLock 改为可替换（RwLock<Arc>），游戏循环无锁读。

### P2 区域与怪物
- `GET/PUT/POST /api/zones` — 区域列表、出生点/传送门/怪物刷新点编辑、新地图接入（均落库）；
- 保存后该区在场怪物按新配置重建；
- "新增地图"：服务器列出资源目录内可用 .map → 选择生成边车模板
  （出生点默认地图中心自动吸附）→ 客户端小地图帧号提示待配。

### P3 增强
- 图标/外观可视选择器：`GET /api/preview/icon/{frame}` 服务器动态解码
  Items.Lib 帧为 PNG，前端网格选图代替手填帧号；
- 变更审计日志（谁在何时改了什么）、一键备份/导入导出；
- 客户端配置联动（技能特效表/小地图帧号外置后同机制维护）。

## 安全

- 与管理台一致：非回环绑定强制 `MIRFORGE_ADMIN_TOKEN`；
- 配置写入全部走参数化 SQL，无文件写入路径；资源预览端点走库名白名单。

### 任务设置（2026-08 改版）

原先是一个 JSON 文本域，要手写 `objectives: [[怪物模板, 数量]]`，写错既不提示也不生效。
现改为结构化表格：

- 列表：id / 名称 / 击杀目标摘要 / 经验奖励 / 前置任务（下拉，自动排除自己）；
- 「目标」行内展开击杀目标表，目标为下拉——**列出各区刷新点模板与所有 BOSS**
  （BOSS 的 `template` 就是它的 id，击杀同样计入任务）；
- 校验：目标必须存在于某个刷新点或 BOSS、数量不能为 0（连同原有的 id 唯一、
  前置存在）。刷新点在区域表里，故与走格校验一起走 `AdminCmd::CheckPlacement`。

目标写错原本是**静默失败**——任务永远推不动且毫无提示，与"商店没有入口"是同一类坑。

### 任务奖励（经验 + 金币 + 物品）

```
cfg_quests        + gold_reward
cfg_quest_rewards   quest_id, item, count, ord      (新表)
```

交付时依次发放经验、金币、物品。**物品先整单占位检查**：`背包件数 + 奖励件数 >
上限` 就整单不发、提示"背包空位不足"并**保持任务为进行中**（不消耗任务状态，
清理背包后还能再交）——奖励凭空消失这类 bug 最难查，所以宁可拒绝。

校验：奖励物品存在 · 数量 > 0 · 单个任务的奖励总件数不超过背包上限
（否则等于永远交不了）。

管理台：任务行新增「金币」与「物品奖励」两列，「目标/奖励」行内展开区里
除击杀目标外多一张物品奖励表（物品下拉 + 数量）。

### 商店 NPC 的进店入口

商店是通过对话选项里的**「打开商店」动作**打开的，光把类型设成「商店」并上架
商品**不会**让玩家进得了店。为此分两种情况兜底：

- **没配对话页**：服务端给一个缺省页——商店 NPC 直接带「我看看货」入口，
  点 NPC 即可开店（这是最省事的配法，只上架商品就能用）；
- **配了对话页**：必须在某一页里放一个动作为「打开商店」的选项，否则保存时
  被校验拦下并提示"玩家进不了店"。

（早期版本两种情况都只弹一段普通对话，配了货也进不去店，且无任何提示。）

## BOSS 设置（2026-08 追加）

> 与地图设置里的「怪物刷新点」是两回事：刷新点是「一片区域里刷 N 只、30 秒重生」，
> BOSS 是「某个点上唯一的一只、按配置长时间重生、可全服公告」。

**存储**：`cfg_bosses`（id/名称/地图/坐标/形象/HP/伤害/经验/重生秒/游荡半径/公告/启用）
+ `cfg_boss_drops`（物品/概率），两表同事务整体替换。种子 `server/data/bosses.json`。

**运行时**：BOSS 与普通刷新点都落成同一个 `Monster`，走同一套 AI 与生命周期；
差别只在 `respawn`（每只自带间隔，不再是全局 `RESPAWN_TIME`）、`boss`/`announce`
两个标记。实体 id 形如 `boss_{地图}_{BOSS id}`。

**热重载**：保存 BOSS 后立即撤掉旧的、按新配置重新落地（在场的 BOSS 会被重置为
满血回原位——配置既然改了就以新配置为准），普通刷新点不受影响。

**校验**：id 唯一 · 名称非空 · HP > 0 · 重生间隔 > 0 · 掉落物品存在 · 掉落概率
在 0~1 · 地图已接入 · 坐标可站立（后两条与 NPC 一样走 `AdminCmd::CheckPlacement`，
因为走格数据只在游戏循环里）。

**管理台**：侧栏「BOSS 设置」页（位于地图设置之后）。列表可直接改数值，
形象点缩略图从怪物图库选（`/api/spritegrid/monster`），「取点」跳地图页取坐标，
「掉落」行内展开——内含定位段（就地挂那份唯一的瓦片视口，可反复微调坐标）
与掉落表（物品下拉 + 概率）。地图视口上 BOSS 显示为橙色标记，与刷新点的红色区分。

## 实体碰撞（2026-08 追加）

移动原先只做静态地形判定，人可以直接穿过怪、NPC 与其他玩家（走位/卡位/被围都不成立）。
现改为地形 + 实体一起解算：

- `sim::resolve_move` 统一实现，**两端共用**——客户端预测与服务端权威判定必须同规则，
  否则会回弹；沿用「整体 → 只走 x → 只走 y」的三段回退，每个候选位置再过一遍实体判定。
- 阻挡关系：玩家被 其他玩家 / 活着的怪 / NPC 阻挡；怪被 玩家 / NPC 阻挡。
  **怪之间不互挡**——刷新点是按半径随机撒的，互挡会让整窝当场卡死。
- 尸体（死亡动画中或等重生）不挡路。
- **已经重叠的实体不算数**：只拒绝"新压上去"的重叠。否则怪刷在人身上、或两者因
  延迟短暂重合时人就再也动不了了——能原地脱出比严格无重叠重要。

碰撞间距 = `2 × BODY_RADIUS` = 0.7 格。

**刷怪与重生会让开玩家**：`nearest_free` 在老家附近螺旋找一个既可站立、又与在场玩家
保持碰撞间距的落点；被围满时退回"只要站得住"的位置——宁可短暂重叠也不能不刷，
反正 `resolve_move` 允许从重叠里脱出。怪之间不互相让位（同上，刷新点本就按半径随机撒）。
