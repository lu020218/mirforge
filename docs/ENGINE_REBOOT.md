# 引擎重构技术方案 —— 开源现代化传奇引擎（全 Rust）

> 状态：已对齐定案（2026-07-22）。配套排期见 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)。
> 本文档是重构的技术基准：架构、选型、继承范围与关键设计。

## 1. 目标与原则

| # | 需求 | 落地口径 |
|---|---|---|
| 1 | Rust 实现开源现代化传奇引擎，含前后端 | 客户端与服务器均为 Rust；以"可开源发布的通用引擎"为目标，不是一次性游戏项目 |
| 2 | 直接使用市面已有传奇资源 | 引擎运行时**直读原版格式**（.map / WIL/WIX / WZL/WZX / .Lib），资源目录指过去即可跑，无预转换步骤 |
| 3 | UI 现代 MMORPG 风格重设计 | 抛弃经典 UI 复刻；可停靠面板、现代交互，先出设计稿定风格再落地 |
| 4 | 高分辨率支持 | HiDPI/4K 自适应、任意窗口尺寸、UI 不糊；低清精灵有明确缩放策略 |

原则：
- **仓库零商业资源**：引擎与资源彻底分离（OpenMW 模式），仓库只含代码与合成测试样本；
- **双端单一真源**：协议与判定逻辑（碰撞/移动）为共享 crate，从结构上消灭双端镜像漂移；
- **每个里程碑可运行可验收**：不做长期不可见的大爆炸重写。

## 2. 仓库结构（新开干净仓库）

```
crates/
  mir-formats    # 原版格式解码: .map(type0/1/100) / WIL/WIX / WZL/WZX / Crystal .Lib
                 # 纯逻辑无 IO 依赖注入, 金样本(合成)测试
  mir-atlas      # 运行时纹理图集: 按需解压 → GPU 图集页 → 磁盘缓存(二启秒开)
  protocol       # 全部客户端/服务器消息 (serde), 版本协商字段预留
  sim            # 共享判定: 子格行走性/圆形碰撞体/移动步进/8向吸附
server/          # 权威服务器 (现有代码迁入): 战斗/技能/掉落/持久化/断线恢复
client/          # Bevy 客户端: 渲染/预测/UI/输入/音频
tools/           # 后置工具 (编辑器等)
```

许可：**MIT OR Apache-2.0** 双许可。仓库名建议带 open 前缀（待定，用户命名）。

## 3. 技术选型（定案）

| 领域 | 选型 | 理由 |
|---|---|---|
| 客户端引擎 | **Bevy**（跟随最新稳定版） | ECS、wgpu、跨平台（含 WASM 潜力）、社区最大，开源项目最易吸引贡献者 |
| 游戏 UI | **Bevy UI 自绘皮肤化** | 与游戏同一渲染管线/DPI 体系/输入系统；9-slice 贴图 + 设计令牌实现现代 MMO 质感；不引第三方 UI 库（生态死亡率高） |
| 开发工具 UI | **bevy_egui** | 只用于调试面板与将来的编辑器，不出现在玩家界面 |
| 资源加载 | **运行时直读 + 磁盘缓存** | 首启建索引与图集缓存，二启秒开；无预转换步骤 |
| 服务器 | 延续现有 Rust 栈（tokio + WebSocket + SQLite） | 约九成逻辑直接迁入；后续可换 QUIC/UDP 通道，协议层已抽象 |
| 精灵高分策略 | **整数倍最近邻缩放为默认** + 可选超分缓存 | 保像素风不糊；超分作为引擎设置项后置实现 |
| 许可 | MIT OR Apache-2.0 | Rust 生态惯例，商用友好 |

## 4. 资源直读设计（mir-formats + mir-atlas）

**格式矩阵（首发支持）**——解析细节已在旧仓库 JS 实现中全部验证，移植即可：

| 格式 | 说明 | 已验证的关键细节 |
|---|---|---|
| .map type0 | 经典格式 | 头 52B，12B/格列主序，存在位 0x8000 |
| .map type100 | Crystal "0.map" | 头 8B，26B/格，BackLib+i32 图号 |
| .map type1 | "Map 2010" 加密 | 宽高 XOR 解密、15B/格、frontLib 字节 +2 |
| 阻挡位 | 通用 | blocked = backRaw&0x20000000 \|\| frontRaw&0x8000 |
| Crystal .Lib | v2/v3 | 索引表@8/12，GZip ARGB32，BGRA→RGBA，黑=透明 |
| WIL/WIX | Wemade 原版 | M0 移植时按真实样本回归（8bpp 调色板/16bpp 变体） |
| WZL/WZX | 盛大 | 同上（zlib 压缩帧） |

**管线**：`资源目录扫描 → 归一化索引(格式/库号/帧数) → 按需解码 → 图集页(4096²) → LRU 驻留 + 磁盘缓存`。
缓存键 = 文件内容哈希 + 解码器版本，资源更换自动失效。

**地图即内容**：直读原版 .map 后，几百张原版地图开箱即用；服务器侧每张地图配一个
**JSON 边车**（出生点/传送门/刷怪/安全区），行走性直接来自 .map 阻挡位 + 边车覆写。
（因此地图编辑器降为可选后置工具，见开发计划 M6。）

## 5. 客户端架构（Bevy）

模块（Bevy plugin 划分）：`net`（连接/心跳/断线恢复）、`prediction`（本地预测 + 权威校正，判定调 `sim`）、`world_render`（地图分层/精灵/深度排序）、`ui`（界面全量）、`input`、`audio`、`debug`（egui）。

**投影约定**（继承既有结论）：世界=正方形连续坐标格；屏幕投影 48×32（斜视 y 压缩 2/3）；
大砖 96×64 偶数格；front 物件底对齐 + 帧偏移，按行深度与实体混排。

**精度体系**（继承既有结论）：
- 坐标：连续浮点，移动 8 向吸附步进；
- 碰撞：**1/4 格子网格（12×8）+ 圆形碰撞体（r=0.35 格）+ 沿墙滑行**，逻辑在 `sim` crate 双端共享；
- 行走性来源：.map 阻挡位展开 + 边车覆写。

**高分辨率**：
- UI 按逻辑像素布局，`scale_factor` 全程生效，字体矢量渲染；
- 世界层整数倍缩放（1x/2x/3x 自动按窗口选择），最近邻采样保像素锐度；
- 相机可视范围按窗口自适应（大屏看得更远，或可选锁定视野半径——服务器广播半径需配套，M2 定）。

## 6. 服务器迁移

直接迁入（改动小）：账号/会话（含 sessionToken 断线恢复）、角色与持久化（SQLite upsert 模式）、
战斗/技能/掉落/装备、怪物 AI（仇恨/追击/游荡/拴绳）、区域广播分组、任务系统、子格碰撞。

需要改造：
- 地图加载：从"读转换后 JSON"改为**直读 .map**（复用 mir-formats）+ 边车配置；
- 消息类型：从 server 内定义迁到 `protocol` crate（42 消息为基线，加版本协商字段）；
- 判定代码：碰撞/移动抽到 `sim` crate（现服务器实现即蓝本）。

## 7. UI 设计体系（M4 前置出设计稿）

- **设计令牌**：配色（暗色基底+主题色）、字号阶梯、间距、圆角、投影，集中一处定义；
- **皮肤**：9-slice 贴图集（面板/按钮/槽位三态），全部原创绘制（不用任何传奇官方 UI 素材）；
- **布局**：现代 MMO 惯例——底部动作条+状态、右上小地图、右侧任务追踪、可拖拽停靠面板（背包/角色/技能/社交）、免滚动优先；
- 交互先在设计稿评审定案，再进 Bevy UI 实现（避免边写边改）。

## 8. 与现仓库（Lengend25D）的关系

| 现资产 | 去向 |
|---|---|
| Rust 服务器 | **迁入新仓库**（M2/M3 主体） |
| .map/.Lib 解析（JS） | 移植为 mir-formats（逻辑已验证，M0） |
| 三层精度/边缘套过渡/实例化物件等设计 | 设计结论继承（文档随迁） |
| TS/PixiJS 客户端 + Tauri | 退役（保留作行为参考） |
| 转换管线/Web 编辑器 | 退役；编辑器概念在 M6 以引擎内工具重生 |
| 素材库/圈选清单 | 保留在旧仓库，供内容制作参考（新引擎直读原版，无需素材库） |

旧仓库停止功能开发，只作参考；新仓库自 M0 起为唯一主线。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| Bevy 大版本 API 变动频繁 | 锁定版本按里程碑升级；渲染/UI 封装薄适配层 |
| WIL/WZL 变体多（版本/位深/压缩差异） | 金样本测试 + 解码器按"能识别多少读多少"降级策略；社区反馈驱动补格式 |
| 原版低清素材在 4K 观感 | 整数倍缩放默认可用；超分缓存后置为增强项 |
| 双端共享 crate 的编译面积 | sim/protocol 保持零重依赖（no bevy/tokio 依赖） |
| 开源合规 | CI 检查禁止提交二进制资源；文档明确资源自备 |
